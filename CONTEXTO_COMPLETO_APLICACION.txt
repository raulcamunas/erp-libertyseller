1. DESCRIPCIÓN GENERAL
================================================================================

ERP Liberty Seller Hub es un sistema de gestión empresarial (ERP) diseñado
específicamente para agencias y vendedores de Amazon. La aplicación proporciona:

- Gestión de Leads y CRM (Web + LinkedIn)
- Control financiero mensual con facturación
- Calculadora de comisiones para procesar CSVs de Amazon/Sellerboard
- Módulo PPC Agency Hub para gestión de campañas publicitarias
- Employee Tracker para seguimiento de actividad de empleados
- Sistema de autenticación con roles (Admin/Employee)
- Interfaz moderna con diseño glassmorphism

ARQUITECTURA:
- Frontend: Next.js 14 con App Router
- Backend: Supabase (PostgreSQL, Auth, Storage)
- Estilos: Tailwind CSS + CSS personalizado
- Componentes UI: Shadcn/UI + componentes custom
- Iconos: Lucide React
- Gráficos: Recharts
- Formateo de fechas: date-fns
- Procesamiento Excel: xlsx (SheetJS)
- IA: OpenAI API (GPT-4o, GPT-4o-mini)

3.6. COMISIONES (/dashboard/commissions)
-----------------------------------------
DESCRIPCIÓN: Calculadora de comisiones para procesar CSVs de Amazon/Sellerboard

FUNCIONALIDAD:
- Upload de CSV (drag & drop o click)
- Procesamiento robusto de formatos europeos
- Aplicación de reglas por cliente y excepciones por keyword
- Informe detallado con 8 cards de resumen
- Tabla con 11 columnas de datos
- Guardar reportes con slug único para compartir
- Vista pública de reportes (/report/commissions/[slug])

TABLAS:
- clients: Clientes con tasa base de comisión
  * id, name, base_commission_rate (NUMERIC 5,4), created_at, updated_at
  
- commission_exceptions: Excepciones por keyword
  * id, client_id (FK), keyword, special_rate (NUMERIC 5,4)
  * Unique(client_id, keyword)
  
- commission_reports: Reportes guardados
  * id, slug (unique), client_id (FK), period, data (JSONB)
  * status ('draft' | 'final' | 'archived'), created_at, updated_at

PARSER CSV (lib/utils/csv-parser.ts):
- parseNum(): Maneja formato europeo (1 200,50 → 1200.50)
- getVal(): Búsqueda flexible de columnas (case insensitive + regex)
- detectDelimiter(): Detecta ; o , automáticamente
- parseCSV(): Parsea CSV a objetos

CÁLCULO DE COMISIONES:
1. Ventas Brutas = parseNum(Sales)
2. Reembolsos = Math.abs(parseNum(Refund Cost))
3. Facturación Real = Ventas - Reembolsos
4. Base Neta (SIN IVA) = Facturación Real ÷ 1.21
5. IVA Descontado = Facturación Real - Base Neta
6. Comisión = Base Neta × Tasa

REGLAS:
- Tasa base del cliente por defecto
- Si el nombre del producto contiene keyword de excepción → usa tasa especial
- Búsqueda case insensitive

INFORME DETALLADO:
- 8 cards de resumen
- Tabla con 11 columnas: #, Producto, ASIN, Pedido, Ventas, Reembolsos, Fact. Real, IVA, Base Neta, % Comisión, Comisión
- Pie de tabla con totales
- Manejo de errores de parsing

API: POST /api/commissions/process
- Recibe FormData con file (CSV) y clientId
- Procesa CSV y retorna CommissionCalculationData

CATEGORÍA: Core

3.7.3. Optimizar (Fusión) (/dashboard/marketing/[clientId]/optimize)
---------------------------------------------------------------------
Motor de optimización con IA:

FLUJO:
1. Upload de Bulk File (.xlsx) de Amazon
   - El archivo contiene múltiples pestañas:
     * "Sponsored Products Campaigns" (estructura/bids)
     * "Inf. de Térm. de Búsq. de SP" (search terms)
   
2. Smart Parsing:
   - Detecta pestañas automáticamente por columnas
   - Normaliza headers (limpia espacios)
   - Lee datos de estructura y términos de búsqueda
   
3. Mathematical Proposals (El "Intern"):
   - Bleeders: Gasto > 5€ y Ventas == 0 → Puja = 0.05€, crear negativo
   - Winners: ACOS < 10% → Puja * 1.2
   - Harvesting: Término vende y ACOS < 30% en AUTO → Crear Exact en Manual
   
4. AI Filtering:
   - Filtra propuestas "dubiosas" para revisión de IA:
     * Bleeders con alto gasto (>10€)
     * Nuevos términos de harvesting
     * Keywords con posible brand intent
   
5. AI Decision (GPT-4o-mini):
   - System Prompt detallado para validación semántica y estratégica
   - Rechaza ASINs, valida términos reales
   - Mantiene bids para estrategia de conquista
   - Valida sentido común (ej: "gratis" para productos premium)
   
6. Merge Decisions:
   - Combina decisiones matemáticas con decisiones de IA
   - Si IA dice REJECT → descarta cambio
   - Si IA dice MODIFY → usa nuevo bid propuesto
   
7. Review Interface:
   - Tabla de cambios propuestos
   - Columna "Decisión": 🧮 (Algoritmo) o 🧠 (IA)
   - Tooltip con razón de IA si intervino
   - Edición manual de pujas
   - Panel lateral con detalles de cada cambio
   
8. Finalización:
   - Botón "Optimizar Finalmente"
   - Genera Excel con cambios
   - Crea snapshot semanal en base de datos
   - Genera reporte público automáticamente
   - Redirige a dashboard actualizado

APIS:
- POST /api/marketing/dual-process: Procesa Bulk File y genera cambios
- POST /api/marketing/analyze-data: Extrae datos estructurados para análisis
- POST /api/marketing/ai-insights: Genera insights estratégicos con GPT-4o
- POST /api/marketing/generate-excel: Genera archivo Excel con cambios
- POST /api/marketing/calculate-acos: Calcula ACOS global del archivo
- POST /api/marketing/generate-report: Crea reporte público con slug único

    - Snapshots de rendimiento semanal
    - Campos: id, client_id (FK), week_start_date, total_spend, total_sales, global_acos, total_clicks, avg_cpc, avg_ctr, roas, top_products (JSONB), ai_summary, created_at, updated_at

14. ppc_optimization_reports
    - Reportes de optimización PPC
    - Campos: id, client_id (FK), slug (unique), report_data (JSONB), ai_insights, created_at, updated_at

15. tracker_reports
    - Reportes de actividad de empleados
    - Campos: id, employee_id (TEXT), report_date (TIMESTAMPTZ), created_at, updated_at

16. tracker_logs
    - Logs de actividad individuales
    - Campos: id, report_id (FK), domain, url, title, duration_seconds, start_time, end_time, category (generated)

17. employee_payment_adjustments
    - Ajustes de pago para empleados
    - Campos: id, employee_id (TEXT), week_start_date (DATE), adjustment_type, amount, description, created_at, updated_at

RLS (Row Level Security):
- Todas las tablas tienen RLS habilitado
- Políticas: Usuarios autenticados pueden leer/escribir
- Excepciones:
  * tracker_reports y tracker_logs: Funciones SQL con SECURITY DEFINER para bypass RLS desde API externa
  * commission_reports y ppc_optimization_reports: Lectura pública por slug

TRIGGERS:
- update_updated_at_column(): Actualiza updated_at automáticamente
- handle_new_user(): Crea perfil al registrarse
- on_auth_user_created: Ejecuta handle_new_user()
- update_company_prospects_updated_at: Actualiza updated_at en company_prospects

FUNCIONES SQL:
- insert_tracker_report(p_employee_id, p_report_date): Inserta reporte con SECURITY DEFINER
- insert_tracker_logs(p_logs JSONB): Inserta múltiples logs con SECURITY DEFINER

STORAGE BUCKETS:
- finance-attachments: Para archivos de finanzas
  * Límite: 50MB por archivo
  * MIME types: pdf, jpg, jpeg, png, xlsx, xls, csv

SISTEMA DE ROLES:
- admin: Acceso completo (incluye /admin/* y /dashboard/*)

MIDDLEWARE (middleware.ts):
- Refresca sesión de Supabase
- Protege rutas según rol:
  * /admin/* → Solo admin
  * /dashboard/* → Admin y employee

  * /report/* → Públicas (reportes compartidos)
- Redirige no autenticados a /auth/login
- Redirige employees que intentan acceder a /admin/* a /dashboard

TRIGGERS:
- handle_new_user(): Crea automáticamente un perfil cuando un usuario se registra
- on_auth_user_created: Trigger que ejecuta handle_new_user()

PERMISOS POR APLICACIÓN:
- Configurados en lib/config/apps.ts
- Filtrados en AppSidebar según permisos del usuario
- Admin tiene acceso a todas las apps

8. FLUJOS DE TRABAJO PRINCIPALES
================================================================================

8.1. FLUJO DE AUTENTICACIÓN
----------------------------
1. Usuario visita /auth/login
2. Ingresa email/password
3. Supabase Auth valida credenciales
4. Middleware verifica sesión y rol
5. Redirige según rol:
   - Admin → /dashboard o /admin
   - Employee → /dashboard

8.2. FLUJO DE LEADS
-------------------
1. Lead llega desde n8n → POST /api/webhooks/leads
2. Se valida y guarda en tabla leads
3. Usuario ve leads en /dashboard/leads
4. Puede cambiar estado (nuevo → contactado → perdido)

8.3. FLUJO DE LEADS WEB
-----------------------
1. Lead llega desde formulario web → POST /api/webhooks/web-leads
2. Se guarda en tabla web_leads
3. Notificación en tiempo real a usuarios conectados
4. Usuario ve lead en Kanban board
5. Drag & drop para cambiar estado

8.4. FLUJO DE LINKEDIN PROSPECCIÓN
-----------------------------------
1. Usuario crea empresa objetivo
2. Agrega prospectos dentro de la empresa
3. Asigna agente (Raul/Mario)
4. Cambia estado del prospecto (identificado → contactado → mensaje → respondido)
5. Historial de cambios se guarda automáticamente

8.5. FLUJO DE FINANZAS
-----------------------
1. Usuario selecciona mes/año en /dashboard/finances
2. Se crea/obtiene periodo (finance_periods)
3. Usuario agrega movimiento (ingreso/gasto)
4. Puede adjuntar archivos (facturas)
5. Se calculan totales y se muestra gráfico

8.6. FLUJO DE COMISIONES
------------------------
1. Usuario selecciona cliente en /dashboard/commissions
2. Sube CSV (drag & drop o click)
3. API procesa CSV con parser robusto
4. Aplica reglas del cliente y excepciones
5. Calcula comisiones (quitando IVA y reembolsos)
6. Muestra informe detallado
7. Opcional: Guarda reporte con slug
8. Opcional: Comparte reporte público

8.7. FLUJO DE OPTIMIZACIÓN PPC
-------------------------------
1. Usuario selecciona cliente PPC
2. Va a "Optimizar (Fusión)"
3. Sube Bulk File (.xlsx) de Amazon
4. Sistema parsea archivo inteligentemente
5. Algoritmo matemático genera propuestas:
   - Bleeders → Bajar puja a 0.05€, crear negativo
   - Winners → Aumentar puja 20%
   - Harvesting → Crear Exact en Manual
6. IA filtra y valida propuestas dudosas
7. Usuario revisa cambios en tabla interactiva
8. Puede editar pujas manualmente
9. Click en "Optimizar Finalmente":
   - Genera Excel con cambios
   - Crea snapshot semanal
   - Genera reporte público
   - Redirige a dashboard actualizado

8.8. FLUJO DE EMPLOYEE TRACKER
-------------------------------
1. Empleado instala extensión Chrome
2. Extensión envía datos cada hora → POST /api/tracker/ingest
3. Datos se guardan en tracker_reports y tracker_logs
4. Manager ve actividad en /dashboard/tracker
5. Puede ver vista día o semana
6. En gestión de empleados:
   - Selecciona empleado y semana
   - Ve horas trabajadas y ganancia base
   - Agrega ajustes (comisiones, bonos, deducciones)
   - Ve total a pagar calculado automáticamente

9. CARACTERÍSTICAS TÉCNICAS IMPORTANTES
================================================================================

PARSER CSV ROBUSTO:
- Maneja formatos europeos: "1 200,50" → 1200.50
- Detecta delimitadores: ; o ,
- Búsqueda flexible de columnas: case insensitive + regex
- Maneja caracteres cirílicos en nombres de columnas
- Maneja errores gracefully

PARSER EXCEL (xlsx):
- Lee múltiples pestañas
- Detecta pestañas por nombre o por columnas
- Normaliza headers (limpia espacios)
- Maneja formatos de fecha y número

CÁLCULO DE IVA:
- IVA fijo: 21%
- Fórmula: Base Neta = Facturación Real ÷ 1.21
- Comisión se calcula sobre Base Neta (SIN IVA)

CÁLCULO DE ACOS:
- ACOS = (Gasto / Ventas) × 100
- Se calcula a nivel global y por keyword
- Consistente entre optimizador y dashboard

AI-IN-THE-LOOP:
- Pipeline híbrido: Matemática + IA
- GPT-4o-mini para validación rápida
- GPT-4o para análisis estratégico
- System prompts detallados para evitar alucinaciones
- Fallback si IA falla o tarda >10s

GLASSMORPHISM:
- Efecto visual premium con blur y transparencias
- Fondo animado "liquid glass" con gradientes radiales
- Transiciones suaves entre páginas

RESPONSIVE:
- Mobile-first approach
- Sidebar colapsable en mobile
- Grids adaptativos (1/2/3/4 columnas según breakpoint)

PERFORMANCE:
- Server Components por defecto
- Client Components solo cuando necesario ('use client')
- Caching con cache() de React
- Optimización de imágenes con next/image
- Lazy loading de componentes pesados

REAL-TIME:
- Supabase Realtime para web_leads
- Notificaciones toast cuando llegan nuevos leads
- Actualización automática de Kanban board
